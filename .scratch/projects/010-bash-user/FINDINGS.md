## 1. Run 1 — the grammar-ownership seam over bash: GO

**Acquisition honesty (same as rust, Phase 6):** the PyPI sdist of
tree-sitter-bash ships only the COMPILED `parser.c` + `scanner.c` — NOT the
grammar source. The source comes from GitHub tag `v0.25.1` and is vendored
under `tests/fixtures/bash/` (hermetic): `grammar.json` (179 KB, 101 rules,
49 hidden), `scanner.c` (45 KB), `tree_sitter/` headers, and the repo's own
checked-in `node-types.json` as the ORACLE. The 9.9 MB compiled `parser.c`
is NOT vendored (it is the byproduct, not the source).

**The tool's contract, byte-for-byte:** `derive_schema_for_dir(
tests/fixtures/bash)` → **184 kinds; byte-for-byte vs the CLI's fresh
node-types.json** (`r8_r1_schema_tool_agreement.txt`). And the vendored
oracle (a tag checked in Dec 2025, possibly generated by a NEWER CLI) is
**0 bytes different** from our CLI 0.25.3's fresh output — no upstream
churn this time (rust's 38-byte delta was a different tag).

**What the big multi-context scanner + ~30 externals mean for the schema:**
29 externals split into three buckets by the CLI's own node-types.json
pruning (`r8_r1_schema_shape.txt`):

| bucket | externals |
|---|---|
| **8 named kinds** (visible, extractable) | `heredoc_start`, `heredoc_content`, `heredoc_end`, `file_descriptor`, `variable_name`, `test_operator`, `regex`, `extglob_pattern` |
| **6 anonymous kinds** | `}`, `]`, `<<`, `<<-`, `(`, `esac` (STRING externals appear as anon kinds) |
| **15 pruned** | the hidden helpers (`_heredoc_body_beginning`, `_empty_value`, `_concat`, `_regex_no_slash`, …), the PATTERN external `\n` (PATTERN tokens never appear in node-types.json — the Phase-6 probed fact), `__error_recovery` |

The three supertypes (`_expression`, `_primary_expression`, `_statement`)
appear in the schema as hidden-but-visible kind steps (the Phase-6
"supertypes are never hidden" rule). The scanner's pending-delimiter queue
(`Array(Heredoc)`, `is_raw`, `allows_indent`, serialized) is exactly the
mechanism our `bash_heredoc_scanner.c` adaptation came from — a READ, as
specced; bash is consumed, not authored.

## 2. Run 2 — the light-install consumer, BOTH real-user shapes: GO

`experiment_run2.py` builds the light wheels (`pydantree-pydantree_sitter` +
`pydantree-pydantree_sitter` from src/), creates a FRESH venv with ONLY those +
`tree-sitter-bash` **0.25.1 from the real index**, builds the community
bundle in-repo, and runs the SAME consumer (`consumer_bash.py`) in three
shapes:

| run | interpreter | pydantree_sitter_grammar | rows vs hand truth |
|---|---|---|---|
| in-repo bundle | devenv python (B importable) | importable | ok=True |
| fresh-venv bundle | fresh venv, `Language.load_bundle(dir)` | **unimportable (rc 1)** | ok=True |
| fresh-venv wheel | fresh venv, `tree_sitter_bash.language()` + derived schema bound explicitly | **unimportable (rc 1)** | ok=True |

The extraction payloads are **byte-identical across all three**
(`r8_r2_byte_identical.txt`: all three comparisons true) — the A-surface
comparison from Phase 5/6 over a fifth grammar. The seam does not leak:
`import pydantree_sitter_grammar` fails in the light install.

**Where the wheel and bundle shapes differ for a real user (the honest
answer to the kickoff's question):**

1. **The bundle shape is the one-line artifact** — `Language.load_bundle(dir)`
   binds the schema automatically (checks bound). The wheel shape requires
   binding the derived schema EXPLICITLY: `Language.load(
   tree_sitter_bash.language(), schema="node-schema.json")`. A wheel ships
   no schema — the user must obtain one (this example ships it; for an
   arbitrary grammar: run the B-side schema tool once, or `pydantree_sitter.schema`
   directly). That is the ONE real extra step the wheel shape imposes — and
   it is exactly the seam's design (the schema is the bridge, derived at
   build time, consumed B-free).
2. **`lang.name` is None for a capsule-loaded bundle** (the wheel shape
   reports `"bash"`) — the Phase-6 registry-leak residual, re-confirmed.
   Harmless for extraction; the example prints kinds instead.
3. **The bundle's grammar.so is OUR gcc build of the same source; the
   wheel's is the upstream precompiled parser** — different compilers, same
   grammar → byte-identical extraction rows. The "hundreds of grammars"
   claim rests on the schema (same derivation) + the parse trees (same
   grammar), not on which binary won.

## 3. Run 3 — the extraction task vs hand truth: PASS, plus which surface features bash needed

Hand truth written FIRST (in `examples/bash-extract/sample.sh`'s header +
`ground_truth.json`, from bash's semantics), then the models. Corpus: a
hand-authored `sample.sh` (both function forms, plain/export/function-local
assignments, `<<`/`<<-`/`<<'…'` heredocs, a `3<<` descriptor heredoc), a
REAL script (`real_script.sh` — a verbatim excerpt of llama-infernal's
`build-xcframework.sh`, MIT, Bullish Design — 19 top-level options, 1
function, 1 module.modulemap heredoc), and `unclosed.sh` (lenient-EOF
heredoc). **Every row matched hand truth in all three run shapes** (34 rows:
3+1 functions, 5+19 assignments, 6 heredocs).

**Which A-surface features bash's shape actually needed:**

- **`capture_kind` — NEEDED, and it was broken for required fields (fixed).**
  `heredoc_redirect`'s delimiter/body/end are POSITIONAL children (no CST
  fields) — exactly the Phase-6.5 markdown surface, but the bug only showed
  over bash: `_field_is_query_optional` missed `_CaptureKind` in its marker
  tuple, so EVERY capture_kind field emitted `?` (a required heredoc_start
  could match vacuously, then fail materialization with "field required" —
  first hit over `3<<FDBODY`, where the descriptor-first child order made
  the vacuous path reachable). Fixed (one-line marker-tuple addition) +
  regression test (`test_capture_kind_optionality_quantifies_only_optional_fields`).
- **Mixed field + positional ordering — NEEDED, workaround documented.** The
  emitted query's child order follows model-field order; tree-sitter matches
  mixed field+positional patterns IN CST order (empirically probed: a wrong
  order is an "Impossible pattern" QueryError at compile). Bash: the
  `descriptor` field precedes the positional heredoc trio, so it comes
  first in the model. A real user hits this as a cryptic QueryError — the
  escape hatch is field ordering (documented in the example README + the
  model docstring). A machinery improvement (early error, or reorder) is a
  candidate, not a blocker.
- **Optional captures (`str | None`) — NEEDED and correct.** `descriptor`
  (None for `<<EOF`, "3" for `3<<EOF`) and `heredoc_end`. The Phase-6.5
  `?`-quantifier fix held.
- **`validate_with` — active in every run** (Jobs 1/3/4 before parsing);
  it REJECTED my first instinct (`redirect: str | None = capture("redirect")`
  — see catalog item 3) — the checks doing their job over a new grammar.
- **`compiled_source`** — the three derived .scm patterns are in
  `r8_r3_compiled_source.scm` (a user can diff them; the Heredoc pattern
  shows the descriptor-first ordering).
- **Stubs (`generate_stubs`) — good quality over bash**
  (`r8_r3_bash_stubs.pyi`): `heredoc_redirect` gets descriptor/argument/
  operator/redirect/right field accessors + `children(heredoc_start/body/
  end|pipeline)` overloads; `function_definition` name/body/redirect;
  `variable_assignment` name/value. Supertypes become aliases
  (`_statement = … | function_definition | …`).
- **Record mode — did NOT fit** (a finding, not a gap): bash's top level is
  a statement list with no key/value container node; record mode is for
  config-file grammars (cfg/JSON/INI). The direct-child path gives
  "top-level only" semantics for free instead.
- **Name-based kind inference — not triggered** (the Phase-6 residual):
  `value: str` worked via raw-text coercion over number/string/word/
  command_substitution; no `NodeKind` override needed anywhere.

## 4. Run 4 — the example + the friction catalog

**The artifact** (`examples/bash-extract/`): `extract.py` (the models +
extraction, prints typed rows, self-checks vs `ground_truth.json`),
`node-schema.json` (derived from the source v0.25.1, committed so the wheel
shape works with zero B), the three corpus scripts, and a README a new user
follows: `uv venv` + light wheels + `tree-sitter-bash` + `python extract.py`

(`r8_r4_example_fresh_venv.txt`: `import pydantree_sitter_grammar` fails, 34 rows match).
Also runs from the dev venv via `--bundle`.

### The friction catalog — every real-user stumble, with the escape hatch

| # | what happened | real gap or residual? | escape hatch / status |
|---|---|---|---|
| 1 | `= capture_kind(...)` made REQUIRED captures query-optional (all emitted `?`) — vacuous matches then failed with "field required" | **real gap** | **FIXED** (marker tuple in `_field_is_query_optional`) + regression test |
| 2 | Mixed field+positional models: wrong field order = "Impossible pattern" QueryError (bash: descriptor precedes the heredoc trio) | real gap (UX) | field order must match the CST — documented in the example; a machinery improvement (early error / reorder) is a candidate, not a blocker |
| 3 | `redirect: str \| None = capture("redirect")` on a function → SchemaCheckError: `file_redirect` is a structural node, not text-yielding | **by design** (the checks are the differentiator) | drop the field, or capture a leaf where the grammar has one; no "raw text of any node" escape exists — honest residual |
| 4 | Unclosed heredoc at EOF: the grammar emits a MISSING `heredoc_end` (empty text) → `end == ""`, not None | real behavior | documented + in the ground truth; `?` handles absent, not missing |
| 5 | `<<'TAG'`: heredoc_start keeps the quotes (`'TAG'`); heredoc_end is clean (`TAG`) | real behavior | documented; strip in a property if you want the clean delimiter |
| 6 | String assignment values keep their quotes (`"/usr/local"`) | real behavior | documented; strip in a property |
| 7 | `export VAR=…` and function-local `local x=…` are NOT matched by `M("program", "variable_assignment")` | **pleasant surprise** | the direct-child path gives "top-level only" for free (export nests under declaration_command) |
| 8 | `lang.name` is None for capsule-loaded bundles | residual (Phase 6) | harmless; wheel shape reports "bash" |
| 9 | Record mode doesn't fit bash's statement list | honest assessment | no container node — record mode stays for config-file grammars |
| 10 | `cat <<A <<B` (two heredocs, one command line) parses with an ERROR — the second `<<` lexes as file_redirect `<B` | **real upstream grammar limitation** (the scanner keeps the queue, the grammar's redirect chain can't chain two heredoc redirects) | one heredoc per command; noted in the README |
| 11 | The devenv.nix task body (`VENV_SP="${config.env.DEVENV_STATE}/..."`) is NOT valid bash — `${config...}` is nix interpolation | acquisition finding | used a REAL sibling-project script (llama-infernal, MIT) instead |
| 12 | The wheel shape needs the schema bound explicitly (a wheel ships none) | by design (the schema is the bridge) | ship/derive node-schema.json once (this example does) |
| 13 | `value` of `VAR=$(...)` is the raw command_substitution text (`$(xcrun ... \| awk '{ print $2 }')`) — quotes/`$()` kept | real behavior | raw node text is the contract; parse the value node if you need structure |
| 14 | Name-based kind inference residual — NOT triggered by bash (no NodeKind needed) | residual (Phase 6) | `NodeKind` remains the typed escape |
| 15 | Field-mode-list wrapper-field residual — NOT triggered by bash (no repeated-field task here; rust covered it) | residual (Phase 6) | moved on |
| 16 | The 38-byte-style oracle drift — DID NOT occur (0 bytes over v0.25.1) | non-event | upstream churn only, and the tool tracks the installed CLI by construction |

## 5. §11 risks re-assessed from this side

- **§11.4 upstream churn** — the bash oracle matches our CLI exactly
  (0-byte delta); rust's 38-byte delta was a different tag. The community
  tool path (CLI byproduct → schema) tracks the installed CLI by
  construction either way.
- **The wheel-vs-bundle distribution question** — both shapes proven on a
  fifth grammar; the wheel shape's one extra step (explicit schema bind) is
  the seam's design, not a gap.
- **The "real-user stumbles are surface bugs" class** — this phase proved
  the class is REAL and valuable: a required-capture bug (item 1) and a
  query-ordering trap (item 2) only surface over a grammar with
  positional-child + field shapes (bash's heredoc redirect). Both are now
  pinned by the bash fixture tests.

## 6. Recommendation

**GO — the seam is ready for real users.** The consumer story holds over a
fifth, genuinely different grammar (positional heredoc children, structural
fields, ~30 externals, multi-context scanner): the light install delivers
the full checked extraction in both real-user shapes, B-free, byte-identical
to the in-repo run; the extraction task matches hand truth; and the example
is a copyable artifact a new user can run first (verified end-to-end in a
fresh venv). The two fixes this phase surfaced (capture_kind optionality,
ordering documentation) are exactly the value of a real-user pass: the
seam was proven, but only a consumer with a real grammar found the bugs.

**The single most important next step: the PUBLISHING REHEARSAL.** Phase 6
named "installable-by-name" as the one blocker between "proven" and
"installable"; the name problem is resolved-in-name (pydantree-branded
distributions) but the distributions have never been published or
installed-by-name from a real index (every wheel-shape test here used
`--find-links` wheelhouses + the ONE community wheel `tree-sitter-bash`).
A rehearsal would: publish the three distributions to a real index
(Tokenless/devpi or Test PyPI), install them BY NAME into a fresh venv
(`uv pip install pydantree-pydantree_sitter pydantree-pydantree_sitter`), run this exact bash
example, and retire the "resolved-in-name but unrehearsed" asterisk. It
should NOT happen before the `pydantree_sitter` name-collision note is re-verified
(the pydantree-branding decision is committed, not re-litigated here).
Second-order candidates (explicitly NOT this phase's job): the mixed-
pattern ordering UX (early error / reorder), per-language scanner copies on
demand, and the wasm path IF a platform story demands one artifact.
